# Identifiers, Schemas & Data-Quality Rules

Schemas: `docs/schemas/*.schema.json` (JSON Schema 2020-12) — event ingestion envelope, ingest response, normalized alarm, topology relationship, incident, impact assessment, work order, metric observation. Representative **live** records from the tested fiber-cut run: `docs/samples/*.json`.

| Rule area | Rule (as implemented) | Where |
|---|---|---|
| **Timestamps** | All stored times are UTC ISO-8601 with `Z`, second precision. `eventTime` must parse as ISO-8601 with zone or the event is rejected (422, dead-lettered). Stored `Received At` is set by the platform. | WebAPI Ruby |
| **Late events** | Event older than 120 s at receipt → accepted, `Late=Yes`, note "late by Ns". Correlation uses event time, so late alarms still join the open group whose root explains them. | WebAPI + correlator join step |
| **Out-of-order** | A clear older than the active instance's first occurrence is **not** applied (orphan-clear, recorded). A clear with no active instance is recorded as orphan; if the raise arrives later, the correlator's repair step clears it. Repeats keep `Last Occurred At = max(existing, event)`. | WebAPI + correlator |
| **Clock skew** | Event > 120 s in the future → clamped to receipt time, `Clock Skew=Yes`, note with original time. | WebAPI |
| **Idempotency** | Key = `tenantId|source|sourceEventId`; unique index `[Tenant ID, Idempotency Key]` (case-insensitive) makes concurrent duplicates impossible; pre-check returns 200 duplicate fast. Every other entity: deterministic business ID + unique `[Tenant ID, ID]`. | Core unique indexes |
| **Duplicate detection (semantic)** | Fingerprint `tenant|resolved resource|canonical type` merges resyncs and cross-source reports (e.g. NMS + manager-of-managers) into one alarm; `Source Systems` lists all reporters; `Occurrence Count` counts them. | WebAPI |
| **External IDs** | `identifiers` form maps every external form of an ID (NE:AID, hostname\|ifname, vendor NE name, CPE hostname, GIS/billing IDs) → internal ID, scoped by source (`*` = any), with validity dates and Match Kind (Exact / Alias / Parent). Resolution: exact → alias → parent NE (first token before `:`/`|`/`/`) → unmatched (alarm kept, fingerprint uses `ref:<raw>`, shown as *unmatched*). | WebAPI + identifiers |
| **Severity mapping** | Per source: optical CR/MJ/MN/WR/CL; syslog 0–7; RAN X.733 words; MoM P1–P5; BMS ALARM/WARN/OK → canonical Critical/Major/Minor/Warning/Indeterminate/Cleared. Unmapped → Indeterminate + note (never dropped). | `engine/catalog.json` (inlined into the tree) |
| **State mapping** | Source state `raise`/`clear` or cleared severity → alarm Active/Cleared; incident, WO, change, notification states are whitelisted state machines (`engine/ops.mjs`), mapped from external ticketing by adapters (📐). | |
| **Metric units** | Canonical: `%`, `ms`, `dBm`, `Mbps`. Conversions from `ratio`, `us`, `s`, `bps/kbps/Gbps`; unconvertible unit → rejected with reason; future sample → Suspect. | `/api/noc/ingest/metrics` |
| **Null / unknown** | Empty string = unknown (Kinetic stores strings). Health `Unknown` ≠ `Healthy`. Unknown condition → `UNKNOWN` type (not service-affecting). Missing monitoring → impact *Inferred*, verification requires confirmation. | everywhere |
| **Stale data** | Monitoring freshness is **observed** (newest received event per source) vs `Freshness SLA Minutes`; inventory freshness from last sync; `Fresh / Stale / Very Stale / Not Configured` shown in topbar, Command Center and Map. Stale/degraded sources never block the workflow. | server `observedFreshness` |
| **Conflicting data** | Two sources disagree → `conflicts` row (values, sources, seen-at, policy value). Impact uses the policy value (authority, then freshness) but lowers confidence by 0.1 and writes the conflict ID into the basis. Measurements that contradict topology downgrade Down → Potential with "possible inventory error". | impact engine |
| **Schema versioning** | Envelope `schemaVersion` 1.0/1.1 accepted; minor versions additive; unknown fields ignored; others rejected (422). Breaking change → new WebAPI slug; old one kept until adapters migrate. Stored records carry `Schema Version`. Form fields only ever added (never renamed — slug/field discipline). | WebAPI + model |
| **PII** | Only `contacts` (and on-call phone) hold PII; read policy `NOC PII Reader` excludes Field Tech/Executive; support view masks email/phone; AI prompts/drafts never include contact data; raw payloads must not carry customer PII (adapter responsibility). 📐 data-subject deletion: remove contact, keep hashed ID in audit. | KSL + server |
| **Tenant isolation** | `Tenant ID` on every row, leading every index; server derives tenant from the user attribute (admins may select); KSL `values('Tenant ID') === identity('attribute:NOC Tenant')` on read and write; ingest caller bound to tenant. **Known gap (verified):** submission Access/Modification policies are not evaluated on *create*. A non-admin cannot create a `Submitted` row via the API ("Only space admins can change the core state of a submission", 403), but a plain POST creates a **Draft** with any `Tenant ID` — including another tenant's — which the creator then cannot read. Engine/server writes use the service identity and always stamp the caller's tenant; screens only read `Submitted` data paths. Mitigation 📐: a `Submission Created` K-WF that deletes Draft rows whose `Tenant ID` ≠ creator's tenant, or a Form "Creation"-style policy if the platform adds one. | model, security.mjs |
| **Reconciliation** | Inventory sync is diff-by-business-key; never deletes (retire via `Valid To`); per-field authority list on `integrations.Authority`; conflicts queue for data stewards. | seed/sync contract |
